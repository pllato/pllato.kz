1. Назначение и цели системы

1.1. Система автоматизирует полный цикл выдачи СГР: приём и предварительная фильтрация заявок → экспертиза документов → принятие решения → оформление и подписание бланка → передача в Единое окно КР → реестровый учёт и личный кабинет заявителя.
1.2. Цели: переход к юридически значимому электронному документообороту (ЭЦП); соблюдение Решения Комиссии Таможенного союза № 299 в части состава реестров и форм бланков; прозрачность для заявителя (отслеживание статуса от приёма до выдачи); автоматическое формирование государственных реестров; разгрузка экспертов — целевой режим: 1–2 сотрудника обрабатывают недельный поток, ответ заявителю за дни, а не месяцы.
1.3. Ограничение ответственности: система готовит обоснования, фильтрует и ускоряет процесс; юридические решения (вердикт экспертизы, утверждение, выдача) принимают уполномоченные сотрудники Департамента. Полная юридическая ответственность за выдачу остаётся за учреждением.
1.4. Платформа: собственная веб-система Исполнителя (не конфигурация Битрикс24 или иной коробки); работает в браузере, установка ПО на рабочие места не требуется. У Заказчика отсутствует действующая система автоматизации — внедрение «с чистого листа».

3. Этап 1 · Окно приёма и предварительная фильтрация

3.1. Карточка заявки с вкладками: Заявитель (тип ИП/ЮЛ, страна, реквизиты, контакты; привязка к справочнику контрагентов), Изготовитель (обязательная связь; поддержка нескольких площадок производства с отдельными адресами), Продукция (множественное поле — несколько продуктов одной группы в заявке; код ТН ВЭД ЕАЭС выбором из справочника), Файлы.
3.2. Обязательные вложения: заявление установленной формы; документы о регистрации заявителя/изготовителя; протоколы испытаний аккредитованных лабораторий; образцы этикеток/маркировки. Состав настраивается по группам продукции.
3.3. Автопроверка комплектности: при отсутствии обязательных вложений — автоматический возврат на доработку с комментарием, какой пункт нарушен; уведомление заявителю (ЛК + email). Неполные заявки не поступают к экспертам.
3.4. Роботы: присвоение входящего номера формата ВХ-№/год; установка статуса «Принято на предварительное рассмотрение»; создание экспертного задания; контроль нормативного срока с эскалацией при приближении дедлайна.
3.5. Задание Единому окну: перечень обязательных полей подачи передаётся на сторону государственного портала (по согласованию с его оператором), чтобы отсев неполных заявок происходил уже на этапе подачи.

4. Этап 2 · Экспертиза (одноэкранное рабочее место)

4.1. Одноэкранник: слева — протокол испытаний во встроенном просмотрщике PDF; справа — динамический чек-лист требований, собираемый из базы знаний по коду ТН ВЭД. Без переключения вкладок и прокрутки между разделами.
4.2. Автоматические проверки чек-листа: (а) лаборатория аккредитована, аттестат действует на дату протокола; (б) область аккредитации лаборатории покрывает выполненные исследования; (в) нормативы протокола соответствуют действующим Единым санитарным требованиям; (г) присутствуют все показатели, предусмотренные для данной группы продукции. Подсветка: зелёный — в норме, жёлтый — на границе допуска, красный — показатель отсутствует или вне нормы.
4.3. Поля эксперта: наименование продукции для СГР (на русском языке, строго по регламенту), срок действия (5 лет / бессрочно / на партию), условия оборота.
4.4. Вердикты: «Соответствует» (заявка уходит на утверждение), «Не соответствует» (мотивировка формируется из красных строк чек-листа), «Требует уточнения» (заявитель уведомляется со списком недостающего и дозагружает документы без новой подачи и потери места в очереди).
4.5. Чек-лист сохраняется в карточке заявки как обоснование вердикта и доступен при проверках.

5. Этап 3 · Принятие решения и бланки

5.1. Маршрут: специалист согласует → руководитель/уполномоченное лицо утверждает. Кнопки «Согласовано» / «Отказ».
5.2. При отказе — мотивированное письмо-отказ из шаблона (PDF) с автоподстановкой оснований; отправка заявителю в ЛК и на email; фиксация в журнале.
5.3. Номерная ёмкость бланков строгой отчётности: справочник бланков серии KG (формат строго ЕАЭС: KG № 0000000) со статусами «На складе» / «Использован» / «Испорчен (акт)». При утверждении робот резервирует следующий свободный номер одной транзакцией БД — коллизии номеров исключены. Испорченные бланки списываются актом.

6. Этап 4 · Бланк, ЭЦП и Единое окно

6.1. Генерация бланка СГР: автоподстановка данных карточки в PDF-шаблон установленной формы с защищённым фоном.
6.2. Подписание — серверное, от имени Департамента: система обращается к сервису подписания по REST (изолированный контейнер криптопровайдера), подписывает документ/XML без участия оператора и без аппаратных носителей на рабочих местах. Очередь подписания; каждый вызов журналируется. У заявителей сохраняются их действующие ЭЦП.
6.3. Интеграция с Единым окном КР: подписанное свидетельство и реестровая запись автоматически передаются в Единое окно; дальнейшую передачу в реестр ЕАЭС выполняет Единое окно (прямая интеграция системы с реестром ЕАЭС не предусматривается). Форматы и регламент обмена фиксируются на этапе технического проектирования совместно с оператором Единого окна.
6.4. Детальная схема API (последовательность вызовов, форматы, обработка ошибок, повторы, журналирование) — обязательная часть ТЗ технического проектирования; на интеграционный модуль предоставляется гарантия отдельной строкой договора.

7. Реестры

7.1. Реестр выданных СГР формируется автоматически при каждой выдаче: номер, дата, продукция, изготовитель, заявитель, эксперт, срок действия, статус (действует / приостановлен / аннулирован). Фильтры по дате, продукции, изготовителю; выгрузки.
7.2. Публичная часть реестра для сайта: открытые колонки (номер, дата, продукция, изготовитель, статус), проверка подлинности СГР по номеру. Служебные данные в публичную часть не попадают.

8. Личный кабинет заявителя

8.1. Подача заявки онлайн (в связке с подачей через Единое окно — оба пути ведут в одну систему), статус-трекер стадий (подана → принята с ВХ-№ → экспертиза → решение → СГР выдано), уведомления на каждом переходе (ЛК + email; SMS — опционально), дозагрузка документов по запросу «требует уточнения», архив выданных СГР со скачиванием подписанного PDF.

9.1. Хранение: плоские индексированные таблицы СУБД; сборка чек-листа — единичный JOIN-запрос с целевым временем ответа до 50 мс при полном классификаторе.

10. Статистика и отчётность

10.1. Панель руководителя: заявки по стадиям, сроки прохождения (в т.ч. нарушение нормативного срока), нагрузка экспертов, выданные СГР по периодам и группам продукции, остаток бланков. Выгрузка в Excel.

13.2. Оплачивается Заказчиком напрямую поставщикам: тарифы удостоверяющего центра и Единого окна, серверная инфраструктура, SMS-тариф, типографские бланки. Юридическая экспертиза текстов форм — на стороне Заказчика; Исполнитель реализует согласованные формы.
