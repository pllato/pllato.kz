### Уточнение выделения 0.17.4

`cwRefine` в верхней панели включает клики для снятия/возврата частей выбранной
CAD-цепочки; Shift + клик выполняет это без переключения. Геометрия не меняется.
`selection-subset.mjs` хранит исходный набор ключей, пересчитывает длину без дубликатов
и нахлёстов. Совпадающие копии переключаются вместе. Ручной набор не расширяется обратно
при изменении геометрии; перенос/удаление применяются только к оставшимся объектам.
Проектная трасса не подменяет длину уточнённого выбора всей назначенной трассой.
Это выбор целых исходных CAD-объектов, не произвольного интервала внутри одной SPLINE
или полилинии. Для последнего нужен отдельный точный разрыв; не имитировать его скрытием.
Последний участок снимается Escape. Само уточнение не меняет ведомость ранее назначенного
кабеля и не создаёт revision. Проверки: subset unit и browser Shift/кнопка/возврат,
пересчёт длины, сохранение набора после переноса, scoped delete/undo.

### Постоянная панель действий 0.17.3

### Редактирование выносок 0.17.2

`leader-workbench.mjs` отдельно выбирает созданные редактором выноски по тексту/линии.
Прямой drag переносит подпись и изгиб с неподвижной привязкой; голубые точки меняются

## Что пользователь строит

Рабочий процесс: открыть большой DWG → выбрать план → создать независимую исполнительную
на свободном месте → повернуть/оформить → править приборы и кабели → назначить марку и
сечение → поставить нужные выноски → получить ведомость длин слева снизу → сохранить
всё редактируемым в новой DWG-копии. Нужны автосохранение, история и отсутствие потерь при сбоях.

Особенно важны: выделение всей трассы вместе с поворотами, сохранение исходной CAD-структуры,
длина при рисовании/выборе, рисование по трём точкам как в графическом редакторе,
перемещение/удаление/копирование приборов и кабелей, цвет кабеля, редактируемые подписи.
Назначенный кабель должен учитываться и без выноски.

## Реализовано к 0.15

- Независимые исполнительные, размещение справа от всех чертежей, показ созданного листа,
  поворот, заголовок, рамка, компас, штамп и ведомость. Большое исходное оформление не пересчитывается при каждом переименовании.
- Единый выбор объекта/кабеля; цепочки LINE/ARC/полилиний, совпадающие копии и короткие
  взаимные касательные нахлёсты. На неоднозначных ветвлениях выбор останавливается.
- Панель «Кабель / объект»: новая плавная трасса по трём точкам, длина, узлы,
  перетаскивание, удаление, копирование/вставка, восемь ACI-цветов, марка/сечение/добавочная длина.
- Выноски привязываются к ближайшей точке кабеля. Ведомость группирует назначенные трассы
  по марке и сечению независимо от наличия выносок.
- Исходные цепочки перемещаются/копируются/удаляются группой; приборы выбираются инструментом
  «Прибор». Копирование сохраняет CAD-типы и атрибуты. Общая геометрия повторяющихся блоков защищена.
- Изменение формы исходной цепочки — отдельная подтверждаемая замена на приближённую полилинию.
  Новая трёхточечная кривая также записывается полилинией, а не точной CAD-дугой.
- Локальная история IndexedDB, контрольные точки перед тяжёлыми операциями; DWG экспорт с повторным чтением.

### Модель данных: не путать уровни

Исходные байты + `doc.nativeOps` + новые примитивы + executive project передаются writer-у.
Экранная сцена не является источником для полного пересоздания DWG.

- `dwg-HANDLE` идентифицирует исходную запись. `shape.entityId` — геометрическая запись,
  `shape.id` — корень; `deviceId` — экземпляр прибора; `entityKey` учитывает корень и матрицу.
  Выбранный штрих и содержащий его INSERT — не одно и то же.
- `selectedChain` содержит ключи для подсветки и отдельные ключи/пути измерения без повторов.
  Подрезка нахлёстов используется для длины, исходные CAD-объекты не обрезаются.
- Executive project version 1: sheets, `nativeHandles`, origin, planCentre, paperUnit,
  metresPerUnit, angle, stamp, routes. Трасса содержит points, brand, section, extraMetres,
  leaders; исходная назначенная трасса дополнительно `sourceIds`/paths; новая — controls/smooth/color.
- Удаление исходного назначенного кабеля должно удалить его запись из ведомости.
  Снятие назначения и удаление геометрии — разные действия.
- Ведомость строится из назначенных трасс, а не распознаётся автоматически из всех текстов DWG.
- Длины требуют правильных единиц/калибровки. Кривые измеряются приближённо; добавочная длина неотрицательна.
- История: IndexedDB `pllato_dwg_recovery`, sources/revisions. Она локальна устройству/браузеру,
  не является облачной резервной копией и не заменяет скачивание DWG.

## Сложные исправления, которые нельзя потерять

- **0.14.3 / PR 801:** ограничение LibreDWG на число объектов владельца ломало большие

  Проверяются окружности, оба конца и касательные; пересечение само по себе не означает кабель.
- **0.14.5 / PR 803:** удалён «Участок». Загрузка, Escape и старый alias `select` ведут
  к выбору объекта/кабеля. В старых скриншотах одиночная дуга часто была следствием этого режима.
- **0.15 / PR 804:** `pllato_color`, пакетный `pllato_copy_objects`, удаление ARC/CIRCLE с
  проверкой зависимостей. Копирование одной цепочки выполняется одним графом, не независимыми
  группами для каждого штриха. Исходные owner-ссылки восстанавливаются и при ошибке.

## Проверки и запуск

Из корня репозитория:

```sh
node --test tests/dwg-*.test.mjs
python3 -m http.server 8817
```

В 0.15 прошли **78 модульных тестов**, native-регрессия и два браузерных сценария
(workbench и полный executive workflow). Это не доказательство для всех DWG.

Playwright на текущем Mac доступен через:

```sh
export NODE_PATH=/Users/platontsay/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules
export DWG_TEST_ORIGIN=http://127.0.0.1:8817
export DWG_CLONE_FIXTURE=/absolute/path/to/synthetic-fixture.dwg
export DWG_EXECUTIVE_MODULE=../app/stroy/dwg/vendor/pllato-executive-engine.mjs
node tests/dwg-executive-native.mjs
node tests/dwg-executive-browser.cjs
node tests/dwg-workbench-browser.cjs
node tests/dwg-cable-chain-browser.cjs
```

`dwg-workbench-browser.cjs` использует порт 8817; прочие тесты могут иметь собственные
значения по умолчанию — проверь начало файла. Native module URL разрешается относительно теста.
Синтетический fixture строится из `tests/dwg-clone-fixture.c` с заголовками и host-библиотекой
той же исправленной LibreDWG. Пример для текущего Mac (новый путь результата обязателен):

```sh
fixture_dir=$(mktemp -d /private/tmp/dwg-fixture.XXXXXX)
cc tests/dwg-clone-fixture.c \
  -I/Users/platontsay/Projects/libredwg-0.14/include \
  -I/Users/platontsay/Projects/libredwg-0.14/src \
  -I/Users/platontsay/Projects/libredwg-0.14/.build-pllato/src \
  /Users/platontsay/Projects/libredwg-0.14/.build-pllato/src/.libs/libredwg.a \
  -lm -o "$fixture_dir/make-fixture"
"$fixture_dir/make-fixture" "$fixture_dir/fixture.dwg"
export DWG_CLONE_FIXTURE="$fixture_dir/fixture.dwg"
```

Частные большие файлы проверяются только локально:
`DWG_OWNER_FIXTURE=/absolute/private.dwg node tests/dwg-large-owner-native.mjs`.
Для точечного клонирования см. переменные `DWG_TEST_FILE`, `DWG_ROOT_HANDLE`,
`DWG_PROBE_HANDLES`, `DWG_SAVE_TWICE` в `tests/dwg-executive-customer-probe.mjs`.
Дампы из `/private/tmp` могут исчезнуть; они не заменяют воспроизводимый тест.

Браузерные тесты обходят gate только локальным interception. Не переносить обход в production.
Ограничение sandbox при старте Chrome (EPERM/SIGABRT) не равно сбою приложения:
запросить разрешённый запуск теста. Не использовать рабочую пользовательскую вкладку.

## Сборка и публикация

Native-рецепт и требования к GPL: [BUILD_EXECUTIVE.md](../../../tests/native/BUILD_EXECUTIVE.md).
WASM и JS-модуль поставляются парой; reader и executive writer — разные движки.

1. Чистая новая ветка от актуального `origin/main`; сохранить чужие изменения.
2. Изменения frontend: unit + соответствующий browser test. Native: дополнительно
   запись/повторное чтение, независимость исходника, большой файл при изменении владельцев.
3. Обновить версию/cache-busters согласованно в HTML, импортах, worker/vendor URL.
   CRM `version.js` к DWG не относится. Для документации новой версии приложения не нужно.
4. При native-изменениях пересобрать и обновить соответствующий GPL source archive.
5. `git diff --check`, проверить только целевые файлы; commit, push ветки,
   `gh pr create`, `gh pr merge --merge --delete-branch` (никакого прямого push main).
6. Дождаться успешного Pages deployment. Проверить live HTML и изменённый модуль,
   а не только результат git push. Приложить PR к задаче и обновить этот документ.

## Оставшиеся ограничения / следующие проверки

- Независимый AutoCAD round-trip: геометрия, атрибуты, цвета, ведомость, размеры и принадлежность объектов.
- Повторить пользовательские кабельные случаи на его текущем файле в режиме целой трассы;
  при остановке исследовать точные типы/handles/концы/слой/цвет/матрицу. Не увеличивать допуск вслепую.
- Реальные ветвления/зазоры требуют выбора пользователем, а не угадывания всей сети.
- Proxy/dynamic/сложные зависимости и некоторые операции с reactors/extension dictionaries
  могут быть отклонены. Предпросмотр не доказывает успешный native export.
- Только 2D model space. Отсутствующие оригинальные CAD-шрифты заменяются свободными;
  точного совпадения со всеми GOST/isocpeur/SHX нет.
- Новые кривые и подтверждённая правка формы исходных кабелей — аппроксимация.
- Проверить присвоение марок скопированным исходным кабелям: копирование геометрии само по себе
  не означает автоматическое назначение всех копий в ведомость.
- Дальнейшее нагрузочное тестирование больших документов, отмены, восстановления после crash,
  квоты IndexedDB, повторного экспорта и переименования. Не заявлять «суперстабильно» по синтетическому fixture.

Не публиковать частные чертежи и логи с их содержимым. Обновляй это состояние по факту
проверок; неподтверждённые обещания из переписки не считать реализованной функцией.
