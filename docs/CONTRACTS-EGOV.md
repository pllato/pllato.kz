# Подписание договоров через eGov

На `contracts.html` создаётся договор и общая ссылка. Любой участник, включая создателя, открывает эту ссылку и подписывает на `sign.html` после заполнения реквизитов. Порядок подписания свободный. Компьютер показывает QR; на телефоне доступны ссылки eGov Mobile и eGov Business. Подписание через NCALayer остаётся доступным.

В универсальном режиме интерфейс не назначает обязательного отправителя, не показывает старые pending-заготовки и выводит количество фактически полученных подписей без общего ожидаемого числа. Существующие подписи сохраняются независимо от старого значения role. Поля role и pending-заготовки в базе сохранены для совместимости старых именных ссылок; они не ограничивают POST по общей ссылке.

Перед передачей документа пользователь видит уведомление о SIGEX и нажимает «Продолжить». Используется публичный basic API SIGEX, без ключей API и новых npm-зависимостей:
https://sigex.kz/support/developers/api-egov-basic/

Оригинал передаётся в `CMS_SIGN_ONLY`, результат сохраняется существующим API Pllato как отделённая `.p7s` подпись. `tsp` не выставляется: наличие доверенной метки времени нельзя выводить только из факта использования eGov. Идентификация сертификата использует существующий best-effort парсер NCALayer; эта интеграция не добавляет серверную криптографическую проверку, OCSP или проверку полномочий представителя.

Состояние операции, реквизиты и полученная подпись временно хранятся в sessionStorage текущей вкладки. После подтверждения сохранения API запись удаляется. При возврате из приложения в перезагруженную вкладку нужно нажать «Продолжить подписание eGov». Полученная CMS повторно не подписывается. SHA-256 оригинала защищает от восстановления подписи к изменившемуся файлу. Неподписанная операция ограничена сроком SIGEX, сохранённая CMS — 24 часами. Для сброса операции в начальном диалоге есть «Начать заново».

Ограничение basic API: передача документа и ожидание подписи используют длинные браузерные запросы. Закрытие вкладки, открытие возврата в другом браузере/новой вкладке, очистка sessionStorage или приостановка сети мобильной ОС могут оборвать операцию. Нужно вернуться в исходную вкладку и продолжить; после истечения срока создать новую операцию. Для полностью независимой от браузера обработки потребуется серверная интеграция с сохранением операции и отдельная настройка провайдера.

Проверено:
- `node --test tests/contracts-egov.test.mjs`: отмена, повреждённый ответ, адреса провайдера, истечение, оригинал документа, повторное получение после обрыва, изменение файла;
- создание QR в реальном API SIGEX без передачи документа/персональных данных;
- CORS для origin https://pllato.kz;
- локальный диалог в браузере, ширина 390px, прокрутка.

До подтверждения полной совместимости нужен реальный проход с ЭЦП на iPhone/Android: открыть персональную/общую ссылку, заполнить реквизиты, перейти в eGov, подписать, вернуться, дождаться сохранения и скачать `.p7s`. Также проверить подпись владельца, отказ в приложении и возврат после перезагрузки. Автотесты не подтверждают реальную криптографическую валидность или поведение мобильной ОС.

## Договоры на плашках проектов

На `app.html` в группе «Работа с клиентами» владельцу реестра доступна кнопка «Договор». Окно загружает PDF/DOC/DOCX до 15 МБ в существующий реестр, сохраняет привязку к `data-app-id` плашки и показывает общую ссылку и число подписей. Можно прикрепить уже существующий договор.

Привязки хранятся серверным Store API в коллекции `project_contracts`: одна запись на пару projectId/contractId, без файлов и токенов ссылок. Сам файл и подписи остаются в contracts/R2. Ошибка сохранения привязки после загрузки не требует повторной загрузки: созданный договор можно прикрепить через список. SessionStorage используется только как подсказка о незавершённой привязке. Коллекция использует действующие права Store API; кнопка доступна тому же аккаунту владельца, что и интерфейс реестра. Новый серверный контроль доступа этим изменением не добавляется.

Проверки: `node --test tests/project-contracts.test.mjs`; локальный браузерный стенд с подменой API — прикрепление существующего договора, загрузка синтетического PDF, получение ссылки и сохранение обеих привязок после перезагрузки. Реальные договоры в этой проверке не загружались.
