# Финансовое планирование

App → «7 Отделение — Админ» → «Финансовое планирование».

Владелец задаёт точный список сотрудников в настройках плашки: просмотр или редактирование. По умолчанию доступ только у владельца. Обычный статус администратора или супер-администратора не даёт доступа. API проверяет список при каждом запросе; приватная коллекция исключена из общей синхронизации.

Таблица на 52 недели: 8 прошлых, текущая и 43 будущих при первом сохранении. Граница недели — четверг 14:00 Алматы. При открытии слева показана прошлая неделя, рядом текущая (подсвечена). Стрелки/выбор недели работают на компьютере и телефоне. Показана одна следующая неделя с пустыми ячейками без сумм, процентов и итогов. Значения появляются после её начала (четверг 14:00 Алматы), при автоматическом обновлении без перезагрузки. Правила будущих начислений сохраняются.

Доход берётся из общего графика кассы, включая USD и исторические корректировки. По умолчанию продвижение — 10% этого дохода, налоги — 2%. Бухгалтерское обслуживание, закупка подписок ИИ, серверы и реклама — ручные расходы.

«Выплаты продавцам» — статья-группа. Нажмите название → «+ Подстатья», введите имя продавца, затем сумму в нужной неделе. Основная статья суммирует подстатьи. В чистой прибыли эта сумма вычитается один раз. Можно создавать и другие статьи с подстатьями через «+ Статья».

Чтобы переместить строку, нажмите её название и «↑ Выше» / «↓ Ниже». Группа перемещается вместе с подстатьями; подстатьи меняют порядок внутри группы. Формулы переписывают ссылки по идентификаторам статей, включая диапазоны SUM. Новые строки добавляются кнопкой «+ Статья».

Формулы: арифметика, скобки, проценты, SUM. `=R1*3%` — ссылка на первую строку текущего столбца; `=C1-C2` — конкретные ячейки; `=SUM(R4:R5)` — диапазон. R зарезервирована для текущего столбца. Формулы не исполняют JavaScript; циклы и деление на ноль показывают ошибку.

Чистая прибыль = доход кассы + ручные доходы − ручные расходы − продвижение − налоги − суммы групп расходов. Расчётные строки не входят в прибыль. Ранее автоматически добавлявшиеся выплаты проектов и остаток после плановых выплат удалены из этой таблицы; реестры выплат проектов не изменены. При миграции старые строки и ячейки сохраняются в закрытой серверной записи для восстановления. Ссылки пользовательских формул на убранные строки помечаются #REF!, вместо скрытой подмены значений.

Изменения ячеек, статей и порядка сохраняются автоматически. Индикатор показывает сохранение, успех или ошибку с повторной попыткой. Запросы выполняются последовательно; правки во время запроса сохраняются следующей версией. Сервер отклоняет конфликт (409), не перезаписывая чужие изменения. Доход обновляется при возврате на страницу и раз в минуту, когда нет открытого редактора или несохранённых правок.

Редактор ячейки предлагает сумму, процент от валового дохода или формулу. Правило действует с выбранной недели до следующего датированного изменения этой статьи. Предыдущие недели не изменяются. Нулевое значение останавливает начисление с выбранной недели. Процент считается от дохода каждой недели; ставка видна даже при нулевом доходе. Старые отдельные значения сохраняют поведение до первого нового правила. Показательный столбец скрыт, но старые ссылки на него поддерживаются. Кнопки «Образец B», «Текущая неделя», «Обновить» и «Сохранить» убраны.

Проверки: `node tests/financial-planning.test.mjs` и `node tests/financial-autosave.test.mjs`.

В ячейке «Выплаты продавцам» можно задать ручную сумму или процент. Это дополнительная выплата: итог группы = ручная часть + подстатьи продавцов. В прибыли итог вычитается один раз. Редактор показывает именно ручную часть.
