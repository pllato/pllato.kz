# Zoom → календарь и материалы сделок

## Статус внедрения

Код подготовлен; живой OAuth, перенос реальной записи и очистка ещё не проверены.
Перед включением требуется завершить настройку General App, получить разрешение
владельца на права приложения, записать секреты и пройти проверку ниже.
Очистка оригиналов Zoom по умолчанию выключена. Автоматического удаления из CRM нет.

## Настройка General App (User-managed)

Redirect URL и OAuth Allow List:
`https://pllato-elc-worker.uurraa.workers.dev/api/zoom/callback`

Strict Mode включён. Подключаем единственного организатора через его аккаунт.
Нужные granular scopes (без account-wide/admin вариантов):

- `meeting:write:meeting`
- `meeting:update:meeting`
- `meeting:delete:meeting`
- `cloud_recording:read:list_user_recordings`
- `cloud_recording:read:list_recording_files`
- `cloud_recording:read:recording`

Webhook URL: `https://pllato-elc-worker.uurraa.workers.dev/api/zoom/webhook`
События: `recording.completed`, `recording.transcript_completed`.
Webhook проверяет HMAC, timestamp, endpoint validation; файлы переносит cron.

Секреты Worker (через интерактивный `wrangler secret put`, не коммитить):
`ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`, `ZOOM_WEBHOOK_SECRET`.
Нельзя менять Client Secret без переподключения: он используется для шифрования
OAuth-токенов в отдельной таблице `zoom_private` (не через общий RTDB endpoint).

После деплоя: Календарь → Zoom → Подключить Zoom → разрешение владельца.
В аккаунте Zoom должны быть разрешены облачная запись и создание транскриптов.
Приложение просит `auto_recording: cloud` для новых встреч. Если Zoom/тариф/язык
не создал транскрипт, код не генерирует текст самостоятельно.

## Данные и обработка

- `zoom_meetings`: task ID → Zoom meeting ID → deal ID; join URL и статус.
- `zoom_files`: один ряд на recording file ID, отдельно UUID экземпляра встречи.
- `zoom_private`: OAuth state, зашифрованные токены, курсоры и блокировки.
- R2 `FILES`, приватный префикс `zoom/`; отдача через CRM auth с проверкой сделки.
- Пять минут: свежие записи за 7 дней + страница архива в месячном диапазоне.
  Архив сканируется до `ZOOM_ARCHIVE_FROM` (по умолчанию 2011-01-01), затем снова.
- Один файл за проход cron; потоковое копирование, проверка размера и R2 HEAD.
  Файлы больше 5 GiB и неожиданные download-hosts остаются в Zoom с ошибкой.
- Ошибки переноса повторяются с увеличением интервала. Оригинал не трогаем.
- Без однозначной связи материалы доступны администратору в «Записи без
  привязки». Выбор сделки привязывает все файлы данного UUID встречи.
- Создание по одному task ID не повторяет POST в Zoom. После неопределённого
  сетевого сбоя статус `uncertain`: сверить встречу в Zoom по agenda `CRM event:`
  и восстановить связь вручную. Не сбрасывать статус вслепую.
- Удаление календарного события отменяет Zoom meeting, но не стирает материалы.

## Хранение

Очистка выключена; scope удаления не запрошен. Включать только после отдельного
подтверждения владельца и добавления `cloud_recording:delete:recording_file`.

`ZOOM_TRASH_AFTER_COPY=true`: после проверенной копии и привязки к карточке
конкретный файл перемещается в корзину Zoom (`action=trash`). Не удаляется вся
встреча — её транскрипт может обрабатываться позже. Поведение квоты/корзины
проверить на реальной записи перед включением. Код не очищает корзину навсегда.

Все видео, транскрипты, аудио, чат и прочие материалы хранятся в CRM бессрочно,
независимо от стадии и воронки. Переход в «Центральный файл» не запускает таймер.
Предыдущее правило 28 дней отменено владельцем 29 сентября 2026 года.
Код автоматического удаления из R2 удалён; старый `ZOOM_RETENTION_ENABLED`
не имеет эффекта. В карточке остаётся явное ручное удаление с подтверждением.

## Проверка перед включением удаления

1. `node --test zoom.test.mjs` (Node с `node:sqlite`).
2. `wrangler deploy --dry-run` и проверка JS модуля страницы.
3. Создать тестовую встречу из карточки/календаря; открыть и скопировать ссылку.
4. Перенести время; проверить время в Zoom; повторить запрос с тем же request ID.
5. Провести короткую запись; дождаться отдельного транскрипта; проверить оба
   файла через карточку и невозможность доступа чужого пользователя.
6. Только после успешного реального переноса включить очистку Zoom и проверить
   освобождение квоты. Копии в CRM остаются бессрочно.

Проверки с моками не заменяют пункты 3–6. Реальных Zoom-данных в тестах нет.
